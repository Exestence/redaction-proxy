# Changelog

## 0.3.0 — 2026-10-13

- Placeholder numbers stay stable across turns when a client resends a placeholder the proxy kept in tool-call arguments (a category outside `toolRestore`, such as `⟦EMAIL_3⟧`). Before, the resent placeholder was escaped to `⟪EMAIL_3⟫` and reserved its number, so the real value was renumbered every turn: earlier messages changed, Anthropic rejected replayed signed `thinking` blocks with 400, the model saw its own tool call altered, and prompt caching broke. The per-client memory now also records which identities each remembered value was bound to. A resent placeholder passes to the upstream as written only when it is anchored in this conversation: its first occurrence in masking order (system, tools and instructions first) is in a resent tool call's model-written input (Anthropic `tool_use` input, Chat Completions `tool_calls[].function.arguments`, and the `arguments`, `action`, `code`, `input`, `queries`, or `operation` of a Responses `*_call` item; not what a tool or the server wrote into such an item, such as `output`, `outputs`, `error`, `results`, or `pending_safety_checks`), or kept by the proxy in the tool-call arguments of a reply that a Responses continuation continues; an anchored placeholder also passes where the request's tool results or other text repeat it. Assistant text and reasoning (Anthropic assistant `text` blocks, Chat assistant `content` and DeepSeek `reasoning_content`, Responses assistant `output_text` and `reasoning` summaries), which usually announce the tool call they precede, neither anchor nor count as the first occurrence. It must also name a number the client's memory binds to exactly one value, that value must occur in the request, and masking the request must still give it that number. A placeholder first written in user text, a tool result, or the system prompt, such as one read back from a file or a summary, is escaped as in 0.2.x even when a later tool call copies it: it may have been written before a restart or for a value that has since expired, so the current value may be renumbered. Residual risk: a client that drops the tool result but keeps the tool call, or a model that writes a placeholder it never saw in this request, can still make a stale placeholder restore to the value that number names now; and an anchored id passes everywhere in the request, so an injected copy of that same id in a tool result restores to the same value (the user's own). Categories kept in tool arguments are written to files and command output as placeholders and stay there; read back after a restart or an expiry, they are escaped. A number the client's requests bound to two values, such as `EMAIL_1` of two conversations, is escaped. A Responses continuation keeps the placeholders its earlier requests passed as written and passes them again where the new input resends them, even after another conversation binds the same number to another value (an id only kept in the earlier reply, never passed, is escaped then), as long as masking still gives each one the original the upstream knows it as; when the numbering moved (memory learned an earlier value, or a value only memory masked expired), the stored placeholders are escaped too, which reserves their numbers, so the upstream's old placeholders come back as written instead of as another value. Otherwise a placeholder is escaped as before, including one a user or content injects: a placeholder that fails the memory checks is escaped on its own; a request whose held placeholders would not keep their numbers escapes them all and is masked again, so detection, the name model included, runs twice for it, and up to three times for a renumbered continuation. With `knownOriginalsTtlSeconds = 0`, after a restart, or once the value expires, the old behaviour applies.
- `maskLocalUsername` (default `true`; environment `REDACTION_PROXY_MASK_LOCAL_USERNAME=1|0`): the command-line proxy masks the name of the account it runs as, and its home directory's last segment when different, as a `terms` entry (`⟦TERM_n⟧`). Claude Code sends the bare user name (`user_identity`) and project-directory names such as `-Users-<name>-project`, which the `PATH` rule does not match. Names shorter than 3 characters and generic account names (`root`, `node`, `runner`, `user`, `admin`, and a few more) are skipped, so the Docker image's `node` user masks nothing. Unlike a listed term, the name never gets a request refused, wherever it occurs: where it also spells a JSON key, a model id, or a tool name (`max` in `max_tokens`, `claude`), it is sent as is, and so is an occurrence glued to letters or digits (`<name>2024`), which the whole-word term match skips. A name that `redaction.terms` lists, in any ASCII case, stays a listed term and keeps its refusals. `loadConfig` takes the account as a new optional third argument.
- Tests only: the pathological-input tests in `adversarial` and `rules-extended` allow 5 s of CPU time instead of 2 s. The same 200 KB input took 0.9 s on one CI run and 2.1 s on the next; the regressions these tests catch took 20 s or more.
- Docker verified (2026-10-13, Docker Desktop 29.6.2, Apple Silicon, linux/arm64, fake local upstream): the image builds (347 MB; 864 MB with `--build-arg NAME_MODEL=1`), runs as the non-root user `node`, refuses to start without `REDACTION_PROXY_AUTH_TOKEN` on `0.0.0.0`, answers 401 without the token, masks and restores an email, a national ID, and a home path in OpenAI Chat Completions JSON, streaming, and Anthropic Messages, loads a config file mounted with `--config /redaction.toml`, and answers a CORS preflight from an allowed origin with 204 without forwarding it (other origins 403). Not tested: the name-model image with a real model, and linux/amd64. The README now says to add `-e REDACTION_PROXY_ALLOW_INSECURE_UPSTREAM=1` for a plain `http://` upstream that is not loopback, such as one reached through `host.docker.internal`.
- npx verified from a local tarball (not on npm yet; 2026-10-14): `npm pack` of 0.3.0 gives 199.9 kB and 60 files; `npx --yes --package=./redaction-proxy-<version>.tgz redaction-proxy --demo` prints the demo output, and without `--demo` the proxy starts on 127.0.0.1:8787. There is no health endpoint: GET requests are relayed upstream.
- Real clients verified against Anthropic Messages (Claude Haiku 5.5, 2026-10-13): Claude Code 2.1.287 with its subscription login (streaming text and the Bash and Read tools; the upstream saw only placeholders for detected values; tool arguments restored per `toolRestore`), where before this release a kept placeholder was renumbered on later turns and the model retried a tool 7 times (now one tool call, 3 requests); and dsh through its pi-ai Anthropic route (text and tools), where before this release Anthropic rejected the replayed signed thinking block with HTTP 400. Not verified: the OpenAI API, Codex CLI, the Anthropic SDK used directly, and `e2e:real` against Anthropic.
- READMEs give the status as this version.

## 0.2.0 — 2026-10-13

- Config files can be TOML (`.toml`) as well as JSON (`.json`), chosen by extension, with the same keys and validation; a path without an extension (`/dev/stdin`) is read as JSON as before, and any other extension stops startup. A syntax error names the file and, for TOML, the line and column, without quoting the file. `config.example.toml` lists every option with its default. Adds the runtime dependency `smol-toml` (BSD-3-Clause).
- `sendWhenMaskFails` (default `false`; environment `REDACTION_PROXY_SEND_WHEN_MASK_FAILS=1|0`): when on, a request whose masking fails is sent instead of refused with 422, partly masked when the leak scan finds a detected value still in it, unmasked when masking throws. This sends detected values to the provider. The reply carries `x-redaction-proxy-mask-failed: 1`, also when the proxy itself answers with an error after masking failed (such as 502 on an upstream redirect or a refused connection), and one warning line names the fields and categories, or the error code, never the values. An upstream-sent copy of that header is dropped. Other refusals are unchanged.
- Stricter config validation: in a file, `debugMasked` and `allowInsecureUpstream` accept only `true` or `false` (a string such as `"true"` stops startup instead of being read as off), and `redaction`, `toolRestore`, and `nameModel` must be tables (a TOML date, an array, a number, or a string stops startup).
- Config errors quote a key or value only when it is a short name-like word (letters, `_` or `-`, at most 24 characters and two digits, no known token prefix such as `sk-`, `ghp_`, `xox`, `AKIA`, or `eyJ`); anything else, including token-shaped text and a non-loopback `host`, prints as `<key>`, `<value>`, `<host>`, or the type.
- `REDACTION_PROXY_DEBUG_MASKED` and `REDACTION_PROXY_ALLOW_INSECURE_UPSTREAM` now override the file both ways and accept only `1` or `0`; any other value stops startup. Before, `0` could not turn off a file's `true` and other values were read as off.
- A JSON config file may start with a UTF-8 BOM, as a TOML file already could. A file named exactly `.toml` or `.json` is read in that format.

## 0.1.0 — 2026-10-09

First release.

- Local proxy for OpenAI Chat Completions, OpenAI Responses, and Anthropic Messages clients: detected private values become placeholders (`⟦EMAIL_1⟧`) before the request leaves the machine and are restored in the reply, streaming included.
- Detector `rules-12`: core rules (email, home paths, credentials, Taiwan IDs and phones, cards, private IPs and hosts, high-entropy strings), international and extended rules on by default in the proxy, configured `terms` and `projectNames`. Optional experimental name model.
- Fail-closed within a request: a detected value still present after masking gets the request refused (422).
- Placeholders inside URLs stay unrestored in replies and tool arguments; tool arguments restore only the categories allowed by `toolRestore` (default `PATH`, `TERM`, `PROJECT`).
- Per-client memory of detected values masks them in later requests for 24 hours (`knownOriginalsTtlSeconds`); it never refuses a request.
- Loopback-only by default; an auth token is required off loopback. Upstream redirects are refused.
- Public benchmark on synthetic multilingual data with frozen held-out sets, compared with Presidio.
- Reviewed in ten adversarial rounds before release; see "Protection scope" and "What it does not protect" in the README for the limits.
